# 基本用法

Stumpless 旨在尽可能简化基本用法，同时仍然支持更复杂的功能。最基本的用法是
`stump` 函数：它接收一个格式字符串和可选的替换参数，并将它们发送到最后打开
的目标。因此，只需调用两个函数即可开始将日志写入文件：

```c
file_target = stumpless_open_file_target( "example.log" );
stump( "The hello world of stumpless." );
```

使用格式说明符加入额外信息：

```c
stump( "Login failed for username %s", "example-username" );
```

如果不需要格式说明符，请使用所需日志函数的 `_str` 版本。任何支持格式字符串
和可变参数的函数都具有对应版本；该版本直接接收原始字符串。这样既更快也更
安全，因为无需再担心转义格式说明符。格式说明符转义不当是导致缺陷和
[漏洞](https://owasp.org/www-community/attacks/Format_string_attack)的常见原因。

```c
// 这可能会引发（也许出乎意料的）问题
stump( "Detected the use of %s to print a string!" );

// 这样安全得多！
stump_str( "Detected the use of %s to print a string!" );
```

请尽量使用 `_str` 函数。如果需要在日志消息中包含信息，请考虑使用
[结构化数据](../../../../../docs/examples/entry/README.md)，而不是格式说明符。
这样可以提高日志代码的安全性和性能，也可能提高日志的索引和搜索效率。

如果需要同时打开多个目标，可以通过 `stumpless_add_message` 函数获得相同功能：

```c
net_target = stumpless_open_udp4_target( "network-target", "example.com" );
stumpless_add_message( net_target,
                       "Login failed for username %s",
                       "example-username" );
```

如果当前使用的是标准库 `syslog` 函数，可以使用 `stumplog` 函数逐步迁移。
`stumplog` 具有相同的函数签名和工作原理：

```c
syslog( LOG_INFO | LOG_USER, "Failed login for %s", username );

// 上面的调用可以直接替换为：
stumplog( LOG_INFO | LOG_USER, "Failed login for %s", username );
```

请注意，标准库符号 `LOG_INFO` 和 `LOG_USER` 仍然有效。它们可以与
`STUMPLESS_SEVERITY_<level>` 和 `STUMPLESS_FACILITY_<level>` 符号自由互换。
如果构建系统中存在 `syslog.h` 头文件，则 `STUMPLESS_*` 符号会被声明为标准库
符号的别名。

使用目标完毕后，请务必将其关闭，以释放目标占用的资源。

```c
stumpless_close_file_target( file_target );
stumpless_close_network_target( net_target );
```

如果确实需要释放所有资源（例如为加快某些操作而创建的缓存），请使用释放所有
资源的函数。请务必在关闭所有目标并销毁通过库创建的其他资源之后，再调用该
函数。

```c
stumpless_free_all(  );
```
