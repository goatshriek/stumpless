## 核心特性
Stumpless 拥有诸多特性，使得在 C 语言中记录日志变得既快速又简单：
 * 记录日志到 [众多目标](#它可以记录到哪些目标) ，如 Splunk、rsyslog、journald、Windows 事件日志 (Windows Event Log)、SQLite 等！
 * 结构化与非结构化日志记录，满足您的不同需求
 * 支持在 Linux、Windows、Mac、FreeBSD、MinGW、MSYS2、Cygwin、DOS 等平台上构建！
 * 线程安全
 * 可在编译期间调整或移除，实现零运行时开销 (zero runtime cost)

 * 易于获取的 [文档](https://goatshriek.github.io/stumpless/docs/c/latest/)、[示例](https://github.com/goatshriek/stumpless/tree/latest/docs/examples) 以及 [支持](https://gitter.im/stumpless/community)。


### 它可以记录到哪些目标？
该库的首要目标是为各种日志目标提供一致的日志记录接口。这意味着您可以专注于定义事件本身以及您希望将它们输出到何处，而无需去寻找其他 SDK 或添加额外的守护进程和插件。Stumpless 可以将日志写入到：
 * 简单的字符缓冲区 (Character buffers)
 * 文件与流 (Files and streams)
 * Unix 套接字 (例如本地的 syslog 守护进程)
 * 网络服务器 (IPv4 或 IPv6，TCP 或 UDP)
 * Systemd Journald 服务
 * Sqlite3 数据库
 * Windows 事件日志 (Windows Event Log)
 * 自定义函数，满足您可能需要的任何其他定制功能！

没有找到您需要的功能？欢迎创建一个附带您请求的 [issue](https://github.com/goatshriek/stumpless/issues/new?template=feature_request.md)，我们会将其整合到我们的 [开发路线图](https://github.com/goatshriek/stumpless/blob/latest/docs/roadmap.md) 中！


## 快速构建与安装
Stumpless 仅需 cmake 和支持 cmake 的构建工具链（如 GCC 或 Visual Studio）即可完成构建。

```sh
# 克隆最新版本的源码树
git clone git@github.com:goatshriek/stumpless.git

# 创建一个新的构建目录
mkdir build
cd build

# 配置新的构建
cmake ../stumpless

# 构建 stumpless (使用 4 个线程 - 可根据需要调整)
cmake --build . --parallel 4

# 安装该库 (您可能需要 sudo 权限来执行此操作)
sudo cmake --install .
```

请查看 [安装说明](https://www.google.com/search?q=../../INSTALL.md)，了解在不同环境下或使用其他工具链构建和安装 stumpless 的更多细节。

## 基础用法

最简单的入门方法是将 `stumplog` 函数作为标准库 `syslog` 函数的直接替代品：

```c
// 如果您习惯这样写：
syslog( LOG_INFO | LOG_USER, "My message #%d", count );

// 那么您可以直接替换为：
stumplog( LOG_INFO | LOG_USER, "My message #%d", count );
```

如果您尚未打开任何特定目标，这将会把日志消息发送到当前平台的默认目标：在 Linux 上是 `/dev/log`，在 Mac 系统上是 `/var/run/syslog`，在 Windows 机器上则是 Windows 事件日志。如果您在调用 `stumplog` 之前打开了一个或多个目标，那么日志将被发送到最近打开的那个目标。

如果您需要更简短的函数调用，可以使用 `stump` 函数将消息发送到当前目标。您可以像使用 `printf` 一样使用格式化占位符：

```c
stump( "Login attempt failure #%d for user %s", count, username );
```

如果您不需要格式化占位符，请使用带有 `_str` 后缀的变体函数：它不仅速度更快，而且更安全！

```c
stump_str( "Login failure! See structured data for info." );
```

如果您想要打开特定目标而不是使用默认目标，只需打开您需要的那个并开始发送消息。例如，记录到一个名为 `example.log` 的文件：

```c
target = stumpless_open_file_target( "example.log" );

// 默认使用最近打开的目标
stump( "Login attempt failure #%d for user %s", count, username );
```

通过网络将消息发送到类似 Splunk 或 rsyslog 等服务同样简单：

```c
target = stumpless_open_udp4_target( "send-to-splunk-example",
                                     "mylogserver.com" ); // 也可以使用 IP 地址
stump( "Login attempt failure #%d for user %s", count, username );
```

如果您配置了多个目标，可以像这样将消息发送到选定的那个目标：

```c
stumpless_add_message( target,
                       "Login attempt failure #%d for user %s",
                       count,
                       username );
```

### 日志级别宏 (Severity Shorthand)

在日志调用中直接指定严重程度 (severity levels) 是非常常见的需求，因此 stumpless 提供了一些宏函数，使代码变得更简洁且更高效。例如，要记录严重程度为 INFO 的消息，您可以这样做：

```c
stump_i( "this gets logged as an info message" );
```

如果您还希望在每条消息中包含源文件、行号和函数名信息，可以使用 `_t`（这里的 't' 代表 trace 追踪）：

```c
stump_t( "this includes source info" );
```

使用这些函数的另一个好处是，只需定义 `STUMPLESS_ENABLE_UPTO` 或 `STUMPLESS_DISABLE_DOWNTO` 宏，就可以在编译时将它们完全移除。这使得在不同构建版本之间切换日志级别变得十分容易，例如在生产版本和调试版本之间切换，而无需修改源代码本身。

```c
// 请确保在包含 stumpless.h 之前定义此宏
#define STUMPLESS_ENABLE_UPTO_INFO

// ...

// 这条日志将会正常记录
stump_i( "I'm doing that thing you asked" );

// 这条调试消息将被完全移除：没有任何运行时性能开销
stump_d( "DEBUG info: %d, %d, %s", thing_1, thing_2, stringy_thingy );
```

查阅 [stumpless/level](https://github.com/goatshriek/stumpless/tree/latest/include/stumpless/level) 目录下的头文件以查看日志级别宏函数的完整列表，或者查看 [日志级别示例](https://github.com/goatshriek/stumpless/tree/latest/docs/examples/severity_level) 了解完整的程序运行情况。
